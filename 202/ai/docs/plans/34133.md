# Carrier Selection Rules Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let merchants define ordered, per-token rules ("if conditions then carrier X") that pick the PrestaShop carrier during order import, behind a global "advanced carrier rules engine" switch.

**Architecture:** Rules are stored in a new ObjectModel `ShoppingfeedCarrierRule` (conditions as JSON in DNF: OR of AND groups). Pure classes in `src/CarrierRule/` build the order's criteria, evaluate conditions and resolve the first matching rule; `ShoppingfeedOrderImportActions::verifyOrder()` calls the resolver when the switch is on. The admin view is a Smarty partial plus plain JS that serializes the rules into one hidden JSON field, validated server side by a form handler.

**Tech Stack:** PHP 7.1-compatible syntax, PrestaShop 1.7.6 → 9.x ObjectModel / Configuration / HelperForm, Smarty, plain JS (jQuery is available in the BO), PHPUnit in the `202ecommerce/prestashop:8.1.5` container.

**Spec:** `202/ai/docs/specs/34133.md` (mockup: `202/ai/docs/specs/34133/carrier-rules-mockup.png`)

## Review Focus

1. **Empty rule / empty group** — a rule saved with no conditions, or a group with no conditions, must never match (otherwise it silently catches every order). Pinned in Task 2 (`testEmptyGroupsNeverMatch`) and Task 5 (handler drops empty groups, rejects rules left with none).
2. **Country stored as name vs ISO** — the UI suggests country *names*; the order carries an ISO code. Rule values must be stored as ISO codes (`FR`, `ES`, `GB`), and `UK` on the order is already normalized to `GB` by `OrderData`. Pinned in Task 5 (`testCountryValuesAreStoredAsIso`) and Task 4 (`testUkOrderMatchesGbRule`).
3. **Rule pointing to a deleted / unknown carrier** — the matching rule's `id_carrier_reference` no longer resolves to a carrier: skip that rule, log it, keep evaluating the next rules, then default carrier. Pinned in Task 4 (`testRuleWithDeletedCarrierFallsThrough`).
4. **Malformed stored data** — invalid JSON in `conditions`, unknown criterion or operator, non-array value for list operators: the condition is false, no PHP warning/fatal during import. Pinned in Task 1 (`testMalformedJsonGivesNoConditions`) and Task 2 (`testUnknownCriterionOrOperatorIsFalse`).
5. **Merchant input noise** — weight typed as `5,5`, values with surrounding spaces or mixed case, duplicate tags: weight normalized to float `5.5`, values trimmed, list values de-duplicated, matching case insensitive. Pinned in Task 5 (`testWeightDecimalCommaAndTrimming`) and Task 2 (`testTextComparisonIsCaseInsensitiveAndTrimmed`).
